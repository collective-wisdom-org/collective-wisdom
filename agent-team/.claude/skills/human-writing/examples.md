# Human writing — examples

Short before/after pairs. Parentheses note what changed.

## Slack (status update)

**Before:** Certainly! I'd be happy to share that we've made great progress on the upload flow — it's worth noting that the backend is now robust and seamless.

**After:** Upload flow is wired on the backend. Frontend hookup is next; I'll ping when it's on staging.

*(Answer first, no em dash, no hype.)*

## UI empty state

**Before:** Welcome to your dashboard! We're thrilled to help you leverage our cutting-edge tools to streamline your workflow.

**After:** No projects yet. Create one to start tracking referrals.

*(Concrete action, no performative enthusiasm.)*

## PR description summary

**Before:** In this PR, we delve into the landscape of authentication and furthermore implement a seamless OAuth integration that empowers users.

**After:** Adds Google OAuth sign-in. Existing email/password login unchanged. New env vars documented in `.env.example`.

*(Facts, scope, no filler transitions.)*

## Email (one ask)

**Before:** Hope this helps! Moreover, please don't hesitate to reach out if you have any questions whatsoever — I'm always happy to assist.

**After:** Can you approve the vendor quote by Friday? Reply here if the amount needs to change.

*(Single ask, no engagement bait.)*

## Spec paragraph

**Before:** It's worth noting that, in today's multi-tenant world, we must additionally ensure that all data is robustly scoped. That said, let's dive into the requirements.

**After:** Every query and mutation must filter by `user_id`. Cross-tenant reads are out of scope for v1.

*(Direct requirement, no signpost intro.)*

## Support reply

**Before:** Great question! Absolutely — you can utilize the export button located in the top-right corner of the screen.

**After:** Use **Export** (top right on the list page). CSV includes all columns from the current filter.

*(No opener template; bold only where it matches UI label.)*
