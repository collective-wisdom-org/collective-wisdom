# Agent role GitHub users and personas: Implementation Plan (CW-38)

Spec: [design](../specs/2026-11-03-cw-38-agent-role-github-users-design.md)

All edits go under `agent-team/` except `docs/agents/project.md`. Tests follow `AGENTS.md` § Testing: one table-driven test per rule, test lines no more than feature lines.

## Tasks

1. **`project_config.role_login(role)`** (`agent-team/scripts/project_config.py`). Roles: `chief-of-staff`, `builder`, `code-reviewer`, `security-reviewer`, mapped to the rows `Chief of Staff login`, `Builder login`, `Code reviewer login`, `Security reviewer login`. Returns the first backticked token, or `None` when the row is missing, empty, `none` (the rows ship as `` `none` `` in backticks, so treat a token equal to `none`, any case, as unset) or `TODO(...)`. A value that is not a GitHub login (`^[A-Za-z0-9](?:[A-Za-z0-9-]{0,37}[A-Za-z0-9])?$`) raises `SystemExit` with a one-line message naming the row. An unknown role raises `SystemExit` too. Add a small command line: `python3 -I scripts/project_config.py login <role>` prints the login or nothing, exit 0; unknown role or bad value exits 2 with the message on stderr. Callers do `role_login(r) or running_login`; no extra helper.
   - Test: one table-driven test in `test_project_config.py` (set, `none`, missing row, bad value, unknown role).
2. **`gh.sh`** (`agent-team/scripts/gh.sh`). Read `AGENT_GH_ROLE`. Unset or empty: today's `exec env -u GITHUB_TOKEN -u GH_TOKEN gh "$@"`. Otherwise resolve the login with `python3 -I "$(dirname "$0")/project_config.py" login "$AGENT_GH_ROLE"` (exit 2 with `gh.sh: <message>` if that fails, no `gh` call). Empty login: today's behavior. A login: `token="$(env -u GITHUB_TOKEN -u GH_TOKEN gh auth token -u "$login" 2>/dev/null)"`; if that fails or is empty print `gh.sh: no gh login for <login>; run gh auth login, then gh auth switch -u <owner>` to stderr and exit 2; else `exec env -u GITHUB_TOKEN GH_TOKEN="$token" gh "$@"`. Never print or write the token. Must pass shellcheck.
   - Test: new `test_gh_sh.py`, one table-driven test. A fake `gh` script in a temp dir first on `PATH` records its environment and args to a file, answers `auth token -u <login>` with a token for known logins and exit 1 for others, and a temp `PROJECT_MD`. Rows: no role (no `GH_TOKEN`, a preset `GITHUB_TOKEN` removed); role with `none` row (same); role with login (fake `gh` sees `GH_TOKEN` equal to the fake token, `GITHUB_TOKEN` removed, args passed through); unknown role (exit 2, fake `gh` never ran); login missing from the keyring (exit 2, message names the login, fake `gh` never ran for the real command).
3. **Trust rules in scripts.** A comment counts when its author is the login of the role that writes it, and when that row is unset, the running account (`gh api user`).
   - `merge_pr.py`: in `read_facts` keep `f["login"]` and add `f["authors"] = {"code": role_login("code-reviewer") or login, "security": role_login("security-reviewer") or login, "builder": role_login("builder") or login}`. `review()` matches `## Code review` against `authors["code"]` and `## Security review` against `authors["security"]`; `stands()` matches `Head moved to` against `authors["builder"]`. The "no ... comment by X" message names the expected login. Keep tests that build `f` without `authors` working by falling back to `f["login"]` (`f.get("authors", {}).get(k, f["login"])`), so existing rows stay valid.
   - `cos_handoff.py`: the review comments filter uses the code reviewer login for `## Code review` and the security reviewer login for `## Security review`, each falling back to `pr["login"]`.
   - `cos_brief.py` `moved_line`: pass the builder login (`role_login("builder")` or the running login) instead of the running login.
   - Tests: extend the `test_merge_pr.py` and `test_cos_handoff.py` tables with rows where the review or note author is the role login (counts) and where it is the running login with the role row set (does not count), and another stranger. For `role_login` in these tests, monkeypatch `project_config.role_login`. Add one small table for `moved_line` in a new `test_cos_brief_moved.py` (builder login counts, running login does not once the login is given as the builder, wrong head returns None).
4. **project.md rows** (`docs/agents/project.md` and `agent-team/templates/project.md`). Four new rows in § Git and GitHub after `Owner login`: `Chief of Staff login`, `Builder login`, `Code reviewer login`, `Security reviewer login`, each with value `` `none` `` and a short note without extra backticks ("the account is created and added to gh; see github-auth.md § Agent users"). In the template the note also says an app may leave them `none`.
5. **Personas doc** `agent-team/docs/agents/personas.md`: the four personas (Chief `cw-chief`, Builder `cw-builder`, Reviewer `cw-reviewer`, Sentinel `cw-sentinel`), role, voice, and a one-line GitHub profile bio each. State that logins are suggestions, real ones live in `project.md`, voice is guidance within the `human-writing` rules, and no headings or signatures change. Link it from `org-chart.md` (a new row group or sentence under Roles; mention which roles share a user) and `agent-team/docs/agents/README.md`.
6. **`github-auth.md`**: new section "Agent users" with the setup steps (create four accounts, set each profile from `personas.md`, invite each as a collaborator, accept, `gh auth login` each, `gh auth switch -u <owner login>`, fill the `project.md` rows). Explain `AGENT_GH_ROLE`, that a wrong setup fails with exit 2 rather than falling back to the user, and that merges stay on the user's login. Add to § Verify the four commands `AGENT_GH_ROLE=<role> ./scripts/gh.sh api user --jq .login`, each must print that role's login.
7. **Skills and adapter prose** (short edits, no copy elsewhere of the ship-loop invariants):
   - `ship-loop` § Team mode: new bullet "GitHub users". The child runs every `./scripts/gh.sh` call with `AGENT_GH_ROLE=builder`, the code review comment with `AGENT_GH_ROLE=code-reviewer`, the security review comment with `AGENT_GH_ROLE=security-reviewer`; `scripts/merge_pr.py` with no role. Update the two `pr comment` mentions in § Build stage accordingly (the reviews are posted as the reviewer roles, the `Head moved to` note as builder).
   - `open-pr` § Agent review comment loop and § Team mode: the review comment command carries the reviewer role in team mode; trusted review-comment authors are the owner login, the four team logins from `project.md` and repo review bots.
   - `security-review` § PR comment loop: the comment is posted with `AGENT_GH_ROLE=security-reviewer` in team mode.
   - `merge-pr` § Team mode: the `Head moved to` note posts with `AGENT_GH_ROLE=builder`; `scripts/merge_pr.py` runs with no role.
   - `chief-of-staff` (and `project-manager`, `write-ticket` team mode): every `./scripts/gh.sh` call and every script that calls it runs with `AGENT_GH_ROLE=chief-of-staff`. Find the single best spot (a rule under its commands section) rather than editing every command.
   - `trackers/github.md` § Conventions: Own login becomes "the Chief of Staff login from `project.md`, or the account running `gh` when that row is `none`"; Team tickets only notes that the team accounts are collaborators with write access, so their tickets pass the check and a user without triage or higher still fails it. Update the `read-comments` line to match. Keep `test_tracker_docs.py` passing.
8. **Closeout** after the PR exists: as-built, spec Shipped, index rows, `docs/superpowers/release-notes/cw-38.md` (per `open-pr` § Closeout docs).
