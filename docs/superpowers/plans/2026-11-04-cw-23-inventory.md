# CW-23 inventory: rules before the refactor

CW-23 splits and tightens the agent-team skills and docs. It changes no rule, gate, lane limit, model default, command or reply template. This file is the proof: Table 1 lists every approval gate, merge gate, repo invariant, `cos_state.py` command, Chief of Staff user command, lane limit, model default and guardrail as it reads on `origin/main` at `96b31eb` (the snapshot first taken at `4be5d07` was re-baselined after CW-51 and CW-55 merged), with the exact rule text. IDs G4, O5, O6, O21, O22, O23 were removed by CW-51 (#64) before this snapshot and are left as gaps; O97 went with them (CW-51 made the successor come from `retiredThreads`, so "never take a `Moved to` link from state" no longer exists on main). Rows G142 and up, M83 and up, S47 and up and O143 and up are rules CW-51 and CW-55 added. After the edits, Table 2 repeats the same IDs with the new file and section. The two tables may differ only in `File` and `Section`. A row that can't be matched is a bug in the edit, not in this list.

Spec: `docs/superpowers/specs/2026-11-03-cw-23-shrink-agent-files-design.md` § Proving nothing changed.

How to read Table 1:

- `Rule` is the text exactly as it appears in the cited file, copied from one line, so `grep -F` finds it. Pipes inside a quoted table row are escaped as `\|` here, which is a Markdown cell escape and not part of the rule. Read this file as source, not rendered: `<angle>` placeholders in a rule are part of the text and a renderer may hide them. A table row from the source file is quoted from its first cell, without the leading pipe.
- `File` is the path in the snapshot of `origin/main` (`agent-team/...`; `docs/agents/project.md`, which is local to this repo; `AGENTS.md` and `agent-team/templates/AGENTS.md`). `Section` is the exact heading text. Rules in the Chief of Staff `SKILL.md` before its first `##` heading sit under its title, `Chief of Staff`.
- `chief-of-staff/reference.md` is included because the refactor replaces it with topic files, and `stop everything`, the start-up steps, the state rebuild and the retired and failed handoff rules live there.
- ID prefixes: `G` approval gate (approval, the relay and `createdBy: "user"` checks, `SPEC READY` and `MERGE READY` requirements, review `PASS` requirements, and the blocked and run-ending rules that guard them); `M` merge gate (`merge-pr`, `scripts/merge_pr.py` preconditions as the docs describe them, phase gates, the head check); `I` repo invariant (`project.md` and ship-loop Repo invariants, the `gh.sh` rule, one ticket = one branch = one PR, branch pattern, the child's `Never:` list); `S` `cos_state.py` command and state rule (`show`, `get`, `apply`, `init` and each `apply` op); `C` Chief of Staff user command (each Commands row, queued-ticket rules, `start the team`, the kill switch steps); `L` lane limit and slot rule (Lanes table, Send or queue, Slot fill, the project manager's Todo fill); `D` model default (Models table, the model switch, each `delegate_task` target); `R` guardrail (each Guardrails bullet of the Chief of Staff and the project manager, plus the project manager's pass order and tracker write limits); `O` other operating rules in the Chief of Staff files (stuck check, rate limit, rotation, helper, cross-repo, reports).
- Verification: a script split every row, unescaped the pipes, and checked each `Rule` with `grep -F` against `git show origin/main:<File>` at `96b31eb`, and each `Section` against a heading in that file (fenced code blocks don't count as headings). All 650 Table 1 rows matched when this file was last updated. Table 2 was checked the same way against the working tree (see below).
