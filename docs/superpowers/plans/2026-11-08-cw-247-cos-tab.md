# CW-247 plan: Chief of Staff tab on the dashboard

Spec: `docs/superpowers/specs/2026-11-08-cw-247-cos-tab-design.md` (the spec is the source of truth; this plan only orders the work).

Dashboard paths are under `agent-team/scripts/dashboard/`, mod paths under `mods/agent-gantt/hooks/`.

## Task 1: mod snapshot fields (`snapshot.ts`, `register.tsx`, `snapshot.test.ts`)

1. `snapshot.ts`: export `pickHeading(text: string): string | null`. Look at the first 5 lines of the prompt, collapse whitespace, trim; the first line matching `^[A-Z][A-Z ]{2,38}[A-Z]\.` gives the match without the period, else `null`. T3's `Act as the <x> agent for this task.` line is not all capitals, so it never matches, and it counts as one of the 5 lines.
2. `buildSnapshot` takes `threadId: string | null` and `heading: string | null` and writes both after `pricing`.
3. `register.tsx`: a `thread` atom (`shape: 'thread-1'`, initial `''`) set once in `ensureHarness` from `T3CODE_THREAD_ID` (empty stays empty), and a `heading` atom (`shape: 'heading-1'`, initial `null as string | null`, plus a `headingSet` flag, or `''` unset / `'-'` none) set once in the `prompt.submit` handler on the first prompt that reaches `beginTask` (the same prompt that names the first task), never changed after. `writeSnapshot` passes both to `buildSnapshot` (empty thread becomes `null`).
4. Test (one table-driven): `pickHeading` for a delegated task with T3's first line then `BACKLOG RANKING. One-shot, read only.` gives `BACKLOG RANKING`; `TEAM MODE. CONTINUE. Run /ship-loop ...` gives `TEAM MODE`; a prompt with no heading gives `null`; a heading on line 6 gives `null`. Extend the existing `buildSnapshot` test for the two new keys.

## Task 2: history (`history.ts`, `history.test.ts`)

1. `HistoryEntry` becomes `{ ticket: string; session: Session } | { role: 'ranking' | 'hygiene'; session: Session }`. `Session` gets an optional `threadId?: string | null` (see Task 3, defined in `api.ts`).
2. `parseHistory` accepts both shapes (a `role` entry needs `role` in `ranking` or `hygiene` and no ticket check), drops anything else, and keeps `threadId` when it is a valid thread id string (shared validator exported from `api.ts`).
3. `recordHistory(history, matched)` keeps working for ticket entries with the 500 cap counting ticket entries only. Add `recordTeamHistory(history, matched: { role, session }[])` (or extend `recordHistory` with a second argument) keeping the newest 50 role entries, separate from the 500 ticket sessions, with the same "newer or equal replaces" rule.
4. `historyByTicket` skips role entries. Add `teamHistory(history): { role, session }[]` returning role entries with `finish()` applied.
5. Test (one): a file with ticket entries, role entries and bad entries parses to the good ones; recording 51 role sessions keeps 50 and no ticket session is dropped.

## Task 3: API (`api.ts`, `api.test.ts`)

1. `Snapshot`/`Session` gain `threadId: string | null` and `heading: string | null` (optional on `Session` so existing tests compile). Export `cleanThreadId(x): string | null` (string, at most 200 chars, `^[A-Za-z0-9:%._-]+$`, else `null`).
2. `cleanSnapshot` unchanged in behavior. Factor the shared body into one helper taking a predicate on the cwd; add `cleanTeamSnapshot(s, now)`: same cleaning, but keeps only non-worktree cwds, and carries `threadId` and `heading` (`heading` a string of at most 40 characters, else `null`). Malformed input returns `null`, never throws.
3. `teamRole(session, state): 'chief' | 'ranking' | 'hygiene' | null` per the spec's table (`chiefSessionId` or `chiefThreadId` first, then heading).
4. `buildApi` gains optional inputs `teamHistory?: { role, session }[]`. It adds `chief` and `pm` to `Api` per spec § 3: `paused` from state `paused === true`; `running` when the raw `main` row has an open last segment and `now - updatedAt <= 60_000`; else `idle`. `threadLink` from `environmentId` and `chiefThreadId` (chief) or the session's `threadId` (pm). `chief.gantt` is the newest matched chief session only; no session means no `gantt` key. `pm` merges live snapshots and history entries by `sessionId` (newer `updatedAt` wins; history ones are `finished`), newest `updatedAt` first.
5. Export `teamSessions(input: { snapshots, state, now }): { role: 'ranking' | 'hygiene'; session: Session }[]` for the server to record.
6. Tests per the spec: one table-driven role-rule test (including the malformed snapshot and the worktree one that stays off the tab) and one for `chief.state` plus newest-first merge of live and history.

## Task 4: server (`server.ts`)

In `recordRound`, also compute `teamSessions(...)` and record them into history; in `api()` pass `teamHistory: teamHistory(history)`. Keep the existing try/catch shape so one failure never takes down the loop. Add a small server test only if one fits the existing test file's pattern without much code (a `/api` response has `chief` and `pm` keys).

## Task 5: page (`page/index.html`, `page/app.js`, `page/app.test.js`)

1. `index.html`: under `#error`, a `div.tabs[role=tablist]` with two `button[role=tab]` (`Ship loop`, `Chief of Staff`, `aria-selected`, `aria-controls`); wrap the existing `#status`, `Merged` heading and `#merged` in `div#panel-ship[role=tabpanel]`; add `div#panel-cos[role=tabpanel][hidden]` containing `#cos`. Tab styles in the existing style block using existing variables (light-dark tokens only).
2. `app.js`: export `renderChief(api)` returning markup for the card (title, state badge, `Thread` link as a copy button like tickets use, gantt placeholder `div.chart-body[data-chief]`; no session shows `No Chief of Staff session in the last 24 hours.`) and the `Project manager` heading plus one row per `pm` entry (role label `Backlog ranking` or `Hygiene`, state badge, Thread copy button, updated `stamp`, `<details class="chart" data-pm="<sessionId>">` with a chart body), ten per page with a pager (reuse the Merged pager markup, with its own `data-pm-page` attribute) and `No project manager threads yet.` when empty. Every field goes through `esc()`.
3. `drawCharts` also fills `.chart-body[data-chief]` and `.chart-body[data-pm]` using `renderGantt`.
4. Shell: `poll()` redraws `#cos` only when its html changed (open details kept like the Merged list does), tab clicks and ArrowLeft/ArrowRight/Home/End move between tabs, the choice is saved in `localStorage` under `dashboard-tab` (access wrapped in try/catch), an unknown or missing value opens Ship loop. Both tabs keep updating on every poll.
5. Test (one): `renderChief` renders the card and an empty-list message, escapes a hostile role-row field, and an exported `tabFromStorage(value)` (or equivalent) maps an unknown value to `ship`.

## Task 6: docs (`README.md`)

Add to § Local dashboard: the two tabs, what the Chief of Staff tab shows (the Chief of Staff card and gantt of its current session, the project manager threads with their gantt, newest first), that the project manager list fills only with the updated agent-gantt mod, and that a root-checkout session never shows on the Ship loop tab. Plain sentences, no em dashes.
